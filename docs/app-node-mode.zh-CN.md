# PeerSpan 应用节点模式

> 把无显示器电脑变成远程应用主机。

## 1. 名称与定位

用户界面名称采用 **应用节点模式（App Node）**，不直接使用“无屏模式”。“无屏”只说明机器没有物理显示器，没有表达它能提供什么能力；“应用节点”则表示这台电脑会向受信设备发布应用、承载计算并返回窗口或终端。

内部技术名称可使用 `Headless App Host`，但不建议直接作为中文产品文案。

典型角色：

- **A/B：交互端**，有显示器，负责显示应用菜单、远端窗口和终端。
- **C：应用节点**，可以没有物理显示器，负责安装并运行实际程序。

程序始终使用 C 的 CPU、GPU、内存、磁盘、网络和本地环境；A/B 只显示结果并发送输入。

## 2. 用户体验

### C 上的首次设置

1. 从 A/B 使用 Windows 远程桌面登录没有物理显示器的 C。
2. 以管理员身份安装 PeerSpan，选择“启用应用节点模式”。安装程序注册开机启动的 Node Service、虚拟显示驱动和当前用户的 Session Agent。
3. 安装并启用 PeerSpan 虚拟显示器，确认虚拟桌面能够正常合成和采集。
4. 选择要发布的 Windows 用户及启动策略。
5. 扫描可启动应用，默认勾选普通桌面应用，排除系统维护和高风险工具。
6. 设置配对码，在 A/B 上完成设备指纹确认。
7. 完成后从 RDP 选择“断开连接”，不要“注销”，以保留当前用户会话和 Session Agent。

### A/B 上的日常使用

```text
PeerSpan
└─ 应用节点
   └─ C（在线，无物理显示器）
      ├─ 搜索应用……
      ├─ 桌面应用
      │  ├─ Visual Studio Code
      │  ├─ Photoshop
      │  └─ 记事本
      └─ 终端与命令
         ├─ PowerShell
         ├─ CMD
         └─ 用户添加的 CLI
```

点击 GUI 应用后，C 启动程序并把窗口作为 A/B 上的代理窗口显示。点击 CLI 后，A/B 打开原生终端视图，命令实际由 C 执行。

应用菜单需要显示：名称、图标、来源电脑、运行状态、GUI/终端类型、是否需要授权以及最近使用时间。多个节点存在同名应用时，必须明确标注运行节点。

## 3. 功能需求

| 编号 | 需求 | 验收重点 |
| --- | --- | --- |
| AN-001 | C 可启用或停用应用节点模式 | 停用后不再发布目录或接受启动请求，已有会话按用户选择结束或保留 |
| AN-002 | C 无物理显示器仍可上线 | 系统服务开机启动，虚拟显示器恢复，断网/休眠后自动重连 |
| AN-003 | C 构建可搜索应用目录 | 支持增量刷新、去重、图标缓存、分类、隐藏和人工添加 |
| AN-004 | A/B 可远程启动 GUI 程序 | 在指定 C 用户会话运行，并关联随后出现的顶层窗口和对话框 |
| AN-005 | A/B 可运行命令行程序 | 使用 ConPTY，正确传输 UTF-8/VT、终端尺寸、Ctrl+C 和退出码 |
| AN-006 | A/B 可管理会话 | 支持激活、最小化、关闭代理、结束进程、断线重连和状态查询 |
| AN-007 | C 可控制发布与执行权限 | 默认允许列表；远程 Shell、参数、提权和文件访问分别授权 |
| AN-008 | 支持 Windows 10/11 | 技术最低版本 Windows 10 1903 x64；正式测试 Win10 22H2/LTSC 2021 与 Win11 |
| AN-009 | 运行和安全事件可追踪 | 记录设备、用户、应用、参数策略、开始/结束时间和结果，不记录终端敏感正文 |
| AN-010 | C 上的文件默认留在 C | 保存对话框和程序工作目录指向 C；跨机文件传输是独立的显式操作 |
| AN-011 | 支持通过 RDP 安装成 Windows 服务 | RDP 内可完成驱动、服务、Session Agent 和配对配置；安装后服务随系统启动 |
| AN-012 | 区分服务在线和 GUI 会话可用 | 用户注销时节点仍在线，但拒绝/排队 GUI 启动并返回明确状态，不显示黑屏 |
| AN-013 | 自动适配每显示器 DPI | C、A/B 的 DPI 或旋转不同时，窗口逻辑尺寸、画面分辨率和输入坐标自动换算；动态变化无需重启会话 |

## 4. “扫描所有程序”的实现定义

Windows 没有一个能返回“所有可由用户正常启动程序”的完整统一 API。遍历磁盘寻找 `.exe` 会得到大量运行库、卸载器、更新器、驱动工具和恶意伪装文件。因此 PeerSpan 应将需求定义成：**尽可能完整地建立可启动应用目录，并允许人工补充，而不是承诺枚举磁盘上的每个 EXE。**

### 目录来源

| 来源 | 用途 | 注意事项 |
| --- | --- | --- |
| 所有用户/当前用户开始菜单 `.lnk` | 普通桌面程序的主要来源 | 解析目标、参数、工作目录、图标和 AppUserModelID |
| HKLM/HKCU 卸载注册表项，含 32/64 位视图 | 补充安装信息和显示名称 | 卸载项不一定包含可启动入口，不能直接把卸载命令发布出去 |
| AppX/MSIX 包与开始菜单应用列表 | UWP/打包应用 | 启动通常依赖 AUMID，不能假定存在直接 EXE 路径 |
| PATH 中的可执行命令 | 构建终端工具目录 | 默认不全部发布，只显示经过规则识别或用户选择的命令 |
| 用户指定目录、快捷方式或命令模板 | 补足绿色软件、自研工具和脚本 | 保存规范化路径、固定参数、工作目录与允许的参数模式 |
| 最近成功启动记录 | 改善搜索和排序 | 不应自动提升权限或改变发布策略 |

### 去重与分类

- 优先使用 AUMID、规范化快捷方式目标、可执行文件路径和发布者签名组合生成稳定 ID。
- 同一应用的多个快捷方式可合并为一个应用，并保留不同启动动作。
- 读取 PE Subsystem、快捷方式目标和启动结果，将条目标记为 GUI、终端或混合类型。
- 默认隐藏卸载器、更新器、崩溃报告器、后台服务、驱动安装器和 Windows 系统维护工具。
- 提供“显示全部扫描结果”和“手工发布”入口，满足高级用户访问绿色软件或内部程序的需求。

## 5. GUI 与命令行程序的启动策略

### GUI 程序

启动链路：

```text
A 发出 LaunchRequest
    -> C 系统服务验证设备、用户与发布策略
    -> C 用户会话 Agent 使用用户令牌启动进程
    -> WinEventHook/进程关联发现顶层窗口组
    -> Windows Graphics Capture 采集窗口
    -> A 创建代理窗口并回传输入
```

不能只依赖新进程 PID 关联窗口：浏览器、Office、UWP 和单实例应用可能把请求交给已有进程。应组合使用启动时间、进程树、窗口事件、AUMID、可执行路径和前台窗口变化进行关联；关联不确定时允许用户从 C 当前窗口列表中选择。

代理窗口及 PeerSpan UI 必须启用 Per-Monitor DPI Awareness V2。C 向 A/B 发送窗口内容物理像素、逻辑 DIP、当前 DPI、旋转和内容边界；A/B 以目标显示器 DPI 创建代理窗口，并用内容区归一化坐标回传输入。窗口被拖到另一块不同缩放的显示器时，应处理 `WM_DPICHANGED`、采用建议矩形并重新协商捕获/编码尺寸。

如果应用启动后没有发现顶层窗口：

1. 若它是控制台子系统，自动切换到终端模式；
2. 若它是后台/托盘应用，在 A/B 显示运行状态，不创建空白窗口；
3. 超时后给出“仍在后台运行”“选择现有窗口”或“结束进程”，而不是无限等待。

### 命令行程序

命令行程序不应通过视频采集 `conhost.exe`。C 使用 ConPTY 创建伪终端，把 VT 字节流发送给 A/B；A/B 使用本地终端控件渲染。

协议至少包含：

- UTF-8 输入/输出字节流和 VT 控制序列；
- 行列数变化；
- Ctrl+C、Ctrl+Break、粘贴和组合键；
- 当前目录、环境模板和字符编码声明；
- 进程退出码、会话结束原因和重连状态；
- 有上限的断线输出缓冲，避免高速输出耗尽 C 的内存。

允许发布固定命令模板，例如“构建项目”“查看日志”，但不能让普通应用权限自动升级成任意远程 Shell 权限。

## 6. C 的服务与会话架构

```text
Windows 开机
└─ PeerSpan Node Service（Session 0，最小权限边界）
   ├─ 设备身份、配对和策略
   ├─ 网络监听与审计
   ├─ 虚拟显示驱动生命周期
   └─ 用户会话协调
      └─ PeerSpan Session Agent（交互式用户会话）
         ├─ 应用目录与用户配置
         ├─ CreateProcessAsUser/进程 Job
         ├─ HWND/窗口组跟踪与采集
         ├─ 输入注入与剪贴板
         └─ ConPTY 会话
```

系统服务不应直接在 Session 0 启动并尝试显示 GUI。用户会话 Agent 才能访问该用户的桌面、应用配置、剪贴板和正常 GUI 环境。

Node Service 可以从 RDP 会话正常安装，并应使用 Windows Service Control Manager 注册为自动启动。它负责确保节点在没有显示器、没有打开 RDP 客户端时仍能被发现和管理；但“安装成服务”并不会解除 Windows 的 Session 0 隔离。GUI 进程仍必须由某个交互式 RDP/控制台用户会话中的 Session Agent 启动。

节点状态不能只有“在线/离线”两个值，至少应区分：

- `ServiceOnline`：Node Service 已上线，可配对、查看策略和执行服务允许的终端任务；
- `GuiSessionReady`：目标 Windows 用户会话已登录且 Session Agent 正常，可启动和投送 GUI；
- `GuiSessionDisconnected`：RDP 已断开但会话仍保留，通常仍可继续运行；需通过实际采集健康检查确认图形管线有效；
- `GuiSessionMissing`：用户已注销或重启后尚未登录，GUI 启动应排队或拒绝并提示重新建立用户会话。

### 无屏与无人值守的区别

- **无物理显示器、RDP 用户已登录**：应用节点首个版本支持。虚拟显示器提供桌面，Session Agent 启动和采集 GUI；配置完成后断开 RDP 而不是注销。
- **RDP 已断开但会话保留**：进程通常继续运行，但 Windows 版本、显示驱动和组策略可能影响 DWM/WGC。PeerSpan 必须进行实时采集健康检查，不能只根据会话仍存在就宣称 GUI 可用。
- **用户已登录但电脑已锁屏**：不保证所有 GUI 仍可捕获或输入；首版应提示“节点已锁定”，允许远程终端继续工作，但暂停普通 GUI 控制。
- **冷启动后无人登录**：系统服务和受限终端能力可以上线；普通 GUI 启动需要交互式用户会话，首版不得静默使用明文自动登录密码规避该限制。
- **真正无人值守 GUI**：作为后续独立安全特性，需设计专用节点账户、凭据保护、会话建立、锁屏和本地访问策略。

Windows 组策略可设置断开的远程桌面会话超时并自动注销。安装器应检测并提示相关策略，但不应在未告知管理员时修改域策略。若管理员主动注销，PeerSpan 必须把 GUI 能力标记为不可用；Node Service 本身继续运行。

## 7. 安全模型

应用节点比普通屏幕串流风险更高，因为它具有远程启动程序的能力。

- 节点仅接受已配对且未撤销的设备证书，所有控制和媒体连接加密。
- 默认使用“允许列表”；“发布全部普通应用”必须由 C 管理员显式选择。
- 远程 Shell、任意可执行路径、任意参数、管理员提权和网络路径分别设置权限，不能由一个总开关全部放开。
- 首版不支持从 A/B 无提示地通过 C 的 UAC 对话框。提权应用应拒绝启动或要求 C 侧预授权规则。
- 进程使用 Job Object 管理，支持查看资源占用、结束进程和节点服务异常后的孤儿策略。
- 审计日志记录谁从哪台设备启动了什么、何时结束和结果；终端正文、剪贴板内容和用户文件默认不进入日志。
- 配置一个本地物理紧急停用方式和远程“撤销全部配对”恢复方式；C 无显示器时仍可通过安全模式或命令行停用节点服务。

## 8. Windows 版本范围

- 技术最低版本：**Windows 10 1903 x64（build 18362）**。
- 正式测试：Windows 10 22H2 x64（build 19045）、Windows 10 Enterprise LTSC 2021 x64（build 19044）和受支持的 Windows 11 x64 版本。
- ConPTY 从 Windows 10 1809 提供，但逐窗口 Windows Graphics Capture 的 HWND 互操作能力决定整体最低线为 Windows 10 1903。
- ARM64、Windows Server 和早于 Windows 10 1903 的系统暂不列入首发承诺，后续按驱动、编码器和实际测试结果评估。

## 9. 分阶段交付

### Node Preview

- 通过 RDP 在无物理显示器的 C 上完成服务、驱动和 Session Agent 安装。
- C 保留已登录但可断开的用户会话；Node Service 在 RDP 客户端关闭后继续上线。
- 应用目录、人工发布、远程启动与进程结束。
- GUI 程序先显示在 C 的整块虚拟桌面画布中。
- CMD/PowerShell/自定义 CLI 使用 ConPTY 原生终端。

### Node Beta

- 普通 GUI 应用成为 A/B 上的独立代理窗口。
- 窗口组、弹窗、DPI、剪贴板、断线重连和多应用并发。
- 节点锁定状态、审计、资源限制和应用发布策略完善。

### Unattended Node

- 评估冷启动无人登录时的专用 GUI 会话。
- 专用节点账户、凭据保护、远程解锁/恢复策略经过单独威胁建模。
- 未解决安全桌面、许可证或会话隔离问题前，不将其标记为稳定功能。

## 10. 验收场景

1. C 不连接物理显示器，管理员从 RDP 完成安装；断开 RDP 后 PeerSpan 服务仍在线，A 在 30 秒内看到节点状态。
2. C 的目标 RDP/控制台用户保持登录时，A 能搜索到开始菜单中的普通应用和管理员手工添加的绿色软件。
3. A 启动 C 上的记事本，看到窗口、完成输入并将文件保存到 C；A 关闭代理时可选择是否结束 C 上的记事本。
4. A 启动 C 上的 PowerShell/CMD，运行长输出命令、复制文本、调整窗口大小、发送 Ctrl+C 并看到正确退出码。
5. 未授权设备不能读取应用目录；只有 GUI 权限的设备不能借参数注入获得任意 Shell。
6. C 锁屏、用户注销、网络中断或 A 崩溃时，应用状态明确，既不会无限占用输入，也不会遗留不可管理的虚拟显示器。
7. Windows 10 22H2/LTSC 2021 与 Windows 11 之间至少完成 Win10 -> Win10、Win10 -> Win11、Win11 -> Win10 三组互操作测试。
8. C 用户注销后，A 仍看到 `ServiceOnline`，但 GUI 菜单明确标记“等待用户会话”；重新通过 RDP 登录后无需重装即可恢复 `GuiSessionReady`。
9. C 100%、A 150% 和 C 200%、A 125% 两组配置下，记事本/浏览器代理窗口的逻辑尺寸合理、点击落点准确；将窗口拖到 A 的另一块不同 DPI 显示器后自动重配且不丢失输入焦点。
